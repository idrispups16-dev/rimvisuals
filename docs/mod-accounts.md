# RIMVISUALS mod accounts

The Fabric mod in `idrispups16-dev/RIMVISUALS-Launcher` (0.4.0-alpha.1+) uses browser confirmation at `/account.html?device=CODE#device`. The website uses the same existing Supabase Google/email account and never transmits its password or OAuth session to the mod.

Database migration: `supabase/device-auth.sql`, applied to `pixqnuuvpxxxwaxjntpl` as `mod_browser_device_auth`. Do not rerun it on an already migrated project. Database regression suite: `tests/device-auth.sql` (transaction with generated fixtures and rollback).

RPC contract:
- `mod_device_start(p_verifier_hash,p_session_hash,p_device_name)`: independent SHA-256 hashes of two client-generated 256-bit secrets; returns public `challenge_id`, 8-character hex `code`, 300-second expiry. Bound to 6 starts/IP/minute and 120 total/minute.
- `mod_device_info(p_code)`: authenticated user checks device name, eligibility and whether confirmation replaces an active session. This does not approve anything.
- `mod_device_approve(p_code)`: authenticated, entitlement required; maximum 10 attempts/user/minute, atomic single approval.
- `mod_device_poll(p_challenge_id,p_verifier)`: secret proof, minimum 4 seconds between polls. Approved challenge is consumed once and installs the precommitted session hash, replacing any prior session for that user under a transaction lock.
- `mod_session_validate(p_token)`: bearer credential generated by mod; returns a maximum 75-second lease capped by entitlement/session expiry, never a website session. Sessions expire after 7 days.
- `mod_session_revoke(p_id)`: deletes only the logged-in user's device session.

The browser can read only its own session's non-secret columns. Neither anonymous nor authenticated users can read challenge secrets or session hashes directly. Only hashes are stored. Device names are displayed with `textContent`. Grant/revoke access continues to use the existing admin page and `manual_access` RLS. A registered account alone grants no mod access. Subscriptions count only when active/trialing and unexpired (or lifetime).

Account owners explicitly confirm matching codes; unsolicited codes must not be approved. Replacing/revoking a session takes effect within the current client's 75-second lease. Tokens are bearer credentials: copying a local mod-session file shares authorization until revoked. No hardware fingerprint, offline entitlement, anti-debugger or guarantee against patching is provided.

Validation: website unit tests, browser layout/form checks at desktop/mobile widths, transactional database denial/replay/revocation/expiry/replacement/rate/RLS checks; Fabric build, lease tests and account-screen startup smoke check in GitHub Actions. Full live account confirmation and in-world graphics checks require a user's actual Minecraft installation.
