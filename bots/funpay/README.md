# RIMVISUALS FunPay worker

Статус: код подготовлен, тесты работают без сети. Реальный вход и выдача FunPay пока НЕ проверены, сервер не подключён. До реального контрольного заказа не обещайте покупателям автовыдачу.

Используется сторонняя библиотека FunPayAPI 1.1.0, не официальный API площадки. Совместимость с текущим FunPay необходимо проверить при подключении. Документация: https://funpayapi.readthedocs.io/ru/latest/account.html

## Как работает

Проверяет список оплаченных продаж каждые 30 секунд, заново открывает заказ и проверяет статус PAID, продавца, категорию 223 и точное название одного из трёх тарифов. Обычные сообщения «я оплатил» не используются. В чат заказа отправляется одноразовый ключ, который активируется в аккаунте сайта; затем покупатель скачивает закрытый файл. Покупатель сам подтверждает выполнение на FunPay. Бот не подтверждает заказы, не делает возвраты и не выводит деньги.

Ключи создаются в закрытой странице https://rimvisuals.vercel.app/billing-admin.html (по тарифу) и импортируются по одному на строку. Нельзя импортировать вымышленные коды: они не будут активироваться на сайте. Пароль Supabase боту не нужен.

## Подключение

1. Нужен Linux-сервер с Python 3.12 или Docker и постоянным диском. Бесплатный засыпающий веб-сервис не подходит. Запускайте ровно один экземпляр.
2. Установите зависимости из requirements.txt. В секретных настройках сервера задайте FUNPAY_GOLDEN_KEY и FUNPAY_USER_AGENT из своего аккаунта FunPay. Не отправляйте их в чат и не коммитьте в Git. Ключ даёт доступ к аккаунту продавца: подключать его следует только к своему доверенному серверу.
3. Импортируйте ключи отдельно для каждого тарифа:

```sh
python main.py --import-plan monthly --keys-file /private/monthly.txt
python main.py --import-plan quarterly --keys-file /private/quarterly.txt
python main.py --import-plan lifetime --keys-file /private/lifetime.txt
```

4. Пока новые покупки приостановлены, выполните `python main.py --initialize` один раз: текущие заказы будут исключены, чтобы не выдать второй доступ старым покупателям.
5. Запустите `python main.py` под менеджером процессов с автоматическим перезапуском. Или соберите Dockerfile, подключите секреты и постоянный том /data. Начальная настройка и импорт выполняются с тем же томом.
6. Проведите реальный контрольный заказ: проверить статус FunPay, получение ключа в правильном чате, активацию на новом аккаунте, скачивание, перезапуск без повторной выдачи.
7. Только затем изменить текст трёх лотов с ручной на автоматическую выдачу. Названия лотов должны точно соответствовать PLANS в core.py.

## Ограничения

- При сетевой неопределённости после отправки возможно повторное сообщение с ТЕМ ЖЕ ключом; второй ключ по заказу не расходуется.
- После резервирования ключ не возвращается в свободный запас, даже если заказ отменился. Проверка статуса повторяется перед отправкой.
- Возвраты FunPay и отзыв уже активированной подписки пока обрабатываются владельцем вручную. Бот не обещает автоматический возврат или отзыв.
- Пустой запас останавливает выдачу с сообщением `LookupError` в журнале. Автоматического пополнения и отключения лотов нет; контролируйте остаток до включения продаж.
- Заказы с количеством, отличным от одного, оставляются для ручной проверки, чтобы не выдать неверное число лицензий.
- SQLite содержит действующие ключи. Нужен закрытый постоянный диск и резервная копия; потеря базы может вызвать повторную выдачу. Не удаляйте её при обновлении.
- Не изменяйте название товара до обновления PLANS. Несовпавшие товары не обрабатываются.

Тесты: `python -m unittest discover -s tests` из этой папки. Они не подключаются к FunPay и не отправляют сообщения покупателям.
